# カント付きカーブの段差・描画の乱れ（Issue #2）

> 2026-10-23 確認完了: 開発者から全動作の実機確認完了の報告を受領した。本資料中の過去の未確認・確認待ちと確認手順は当時の調査記録であり、現在の動作確認残件ではない。

## 2026-10-23 Kaizの接続レールへのカント適用漏れ

KaizPatchX 1.10.4の実機フィードバックでは、接続レールが強調される一方、カント整形は成功扱いでも適用されない場合がある。01:27:07/14/17のログは適用成功と更新対象の一部を示すが、接続端点の要求座標がないため、報告された未適用レールのキーまでは確定できない。

コード上では探索の不一致を確認した。クライアントの`collectAffectedRails`はロード済み論理コアの端点座標を照合するが、Kaizサーバーの`findConnectedCantEndpoints`は端点に隣接する1ブロックの所有先しか調べていなかった。自由端点や道床所有先変更によりそのブロックが選択元・別レール・空になると、端点が一致する接続レールを見落とす。サーバーも同じコア列挙で端点を照合し、論理レールキー＋端点indexで重複を除去するよう修正した。許容差は各軸0.001mのまま、近いだけの非接続レールと同じ論理レールは変更しない。

波及範囲はカント整形と、同じ探索を使う分岐・渡り線の既設接続カント退避/平坦化・分割/失敗復元である。新たに見つかる接続先にも既存の在線・対応可否・座標検証を適用する。複線コピーの「コピー元カント優先」仕様は変更しない。AEは既にロード済みコアを探索しており、同じ漏れはない。通常RTMの未対応機能を有効化する変更もない。

関連して、KaizのカントUndoは途中の対象が変更・在線状態の場合に一部だけ復元できてしまうため、全対象のキー・存在・在線を確認してから復元する方式へ変更した。対象一覧は`[SuperRailBuilderX cant] affected rails`へ件数と先頭32キーを出力し、各レールの値は既存`cant-profile`で確認できる。

回帰では隣接ブロックが選択元/空/無関係なレール/接続先の4条件、自由端点、同一論理レールの重複、同向/逆向カント、無関係な端点の保持、在線/未対応時の事前拒否、Undo途中の拒否と再試行を確認した。実機修正確認は未実施。

最新開発ZIPで問題の選択を再実行し、強調された接続レールの端部・中央、適用後とUndo後、再入場前後を比較する。通常/自動分割レールと正負のカントを含める。分岐・渡り線の既設接続側も平坦化と失敗時復元を確認する。再発時は選択順・時刻・スクリーンショットと`logs/latest.log`（`cant`、`cant-profile`行）を開発者から共有する。

## 現在の結論（2026-10-18）

[SRBX Issue #2](https://github.com/hi03s/SuperRailBuilderX/issues/2)の再調査で、**コピー先が既設端点へ吸着すると、コピー元の中央カント・ランダムカントを接続先の値に置き換えてしまうSRBX側の不具合を確認した**。KaizPatch・AEの両版で修正した。既設レールや過去にコピーしたレールを変更する修復処理はない。SRBXPatch JARは変更しない。

その後の開発者指示により、現行の複線コピーは**端部カントもコピー元を優先し、接続先と意図的に一致させない**仕様とした。プレビューもこの値を保持する。サーバーでコピー元のキー・両端座標を照合し、端部・中央・ランダムカントを読み直してから生成する。コピー専用の生成フラグを使用し、生成Aや他ツールの接続端カント継承は従来どおりとする。

回帰テストでは修正前の失敗と修正後の成功を確認した。ただしIssueの旧ログにはカント値がないため、その画像の原因がこの不具合だったかは実機確認待ち。前回はクライアントの複製値だけを確認し、サーバーでの端点解決を十分に追えていなかった。描画側を優先した判断を改め、まずSRBX側の引継ぎ漏れを対処する。

報告環境はSRBX 0.3.1、Minecraft 1.7.10、KaizPatchX 1.10.4。添付画像ではモデル片ごとの段差のような乱れが見える。使用モデルは未特定。開発者も元レールの生成手順を断定できず、SRBXでのカント付き生成またはカント整形後に複線コピーした可能性を挙げている。開発者側でも再現確認を行う予定。

## 確認した引継ぎ漏れと修正

1. `sourcePoint`で中央カントを取得し、`offsetPoint`で複製する。
2. `connectionCandidate`は、吸着先の端カントを反転する一方、中央・ランダムカントにはコピー元の値を保持する。ここまでは正常。
3. サーバーのKaizPatch `resolveBuilderRailPoint` / AE `resolveRailPoint`は既設端点をNBT複製し、端カントだけを反転していた。要求に含まれるコピー元の中央・ランダムカントは無視していた。
4. native `RailMapBasic`は始点の`cantCenter`を終点へも設定して中央カントを共通化する。したがって、コピー先始点が中央カント0の既設レールへ吸着すると、コピー元が5度でも中央0になる。端カントが残る場合は区間の一部だけ傾きが抜ける。接続先の中央値が違えば、その値・符号を拾う可能性もある。

初回修正（2ae0fe5）では、端カントを既設側へ合わせる処理を保ちつつ、要求に中央・ランダムカントが明示されていれば、それを複製したRPへ適用した。0も有効な明示値として扱い、非有限値は配置前に拒否する。明示値がない生成A等の接続は従来の既設継承を維持する。既設RPは変更しない。この経路を共用する移動・組ホーム等も、明示した設定を尊重する。端部カントの現在のコピー仕様は上記の追加指示を適用したもの。

なおカントの負号はレールの向きにも依存する。nativeコンストラクタは端カントとの整合に応じて中央の符号を補正するため、負号や反転だけで不具合とは判断しない。今回確認した問題は、コピー元の明示値がサーバーで無視されること。

### 縦勾配と直近の修正との関連

コピーの4本はいずれも始終点の`anchorPitch=0`。20:37:51の2本と20:38:07の1本は始終点ともY=39.063。20:38:16の1本だけY=39.0625→39.063で、0.0005m（0.5mm）の丸め差がある。明確な縦勾配付きで複製された記録はない。カントによる描画高さの持ち上げは、縦線形の勾配と区別する。

2026-10-14の水平ベジェ修正（cd3caf7）は、生成Aの`orientPair`が縦曲線を分割した外側アンカーを全体へ戻し、さらに分割して制御点を縮める問題への対処。複線コピーは`orientPair`や`planVerticalRailSegments`を通らず、元端点からオフセットを計算して生成する。今回のコピー記録とこの再分割不具合を結び付ける根拠はない。ただし元レールが過去の生成処理で既に変形していた可能性は、このログだけでは否定できない。

2026-10-18、開発者は水平に敷いたカント付きカーブの複線コピーで非再現と報告。カント付きコピー全般で必ず起きる問題とは判断しない。対象モデル、一定カントか変化するカントか、元レールの生成履歴を引き続き切り分ける。

## 実装照合と原因候補

KaizPatchX 1.10.4の実行JARのbytecodeと、ローカル参照ソースd70ef47を照合した。

- SRBXの複線コピーは論理レールの端点を使い、`cantEdge`・`cantCenter`・`cantRandom`を複製する。端点の順序は維持する。今回の調査で、コピー時にこれらを無条件に消す処理は見つかっていない。
- `RailMapSection`は元の論理`RailMapBasic`へ高さ・カントを委譲する。標準描画の`RailRenderSampling`も論理レール共通のサンプルを使う。セクションごとにカントが初期化される根拠は見つかっていない。
- **以前の描画側候補（Issue原因として未確認）**: `RailMapBasic.getRailHeight`は縦線形の高さへ`abs(sin(cant) * 1.5)`を加える一方、`getRailPitch`は縦線形だけの傾きを返す。`RailPartsRenderer`は約0.5mごとにモデル片を剛体配置するため、カントが変わる区間ではモデル片の高さと傾きが整合しない。ロール変化自体も左右端の継ぎ目に影響する。

この計算はSRBX専用ではなくKaizPatchの標準描画にも存在する。ただし報告モデルの描画方法が不明であり、**Issue #2の原因がKaizPatch側だとはまだ断定しない**。モデル固有の形状・スクリプト・ランダムカントなども切り分ける必要がある。高さ差由来のpitchだけを補正しても、ロールが変わるモデル片の左右端までは連続にならないため、暫定の描画補正は導入していない。

## 追加診断

カントが0以外のKaizPatchレールに対し、次の操作で`[SuperRailBuilderX cant-profile]`を出力する。

- `created`: SRBXの共通生成後（複線コピーを含む）。
- `copy-source`: 複線コピー元。
- `cant-update`: カント整形・その復元処理後。

カント整形の成功時には`[SuperRailBuilderX cant] applied targets:`で対象論理キー・端点index・適用角度も記録する。今後は、旧ログでは追えなかった整形対象をコピー元と照合できる。

出力はモデル名、論理レールキー、両端の`edge/center/random`、始点・1/4・中央・3/4・終点の`height/pitch/roll`、隣接描画サンプルの最大高さ差・ロール差・高さ差由来pitchとnative pitchとの差、セクション接続位置・高さ・ロールの最大不一致。単位はmと度。

高さとnative pitchの差はカント変化以外でも生じ得るため、`maxPitchMismatch`だけで異常判定しない。生成前後のカント値、セクション境界の差、画像の乱れる位置を併せて判断する。診断は最大2048区間に制限し、失敗しても操作結果を失敗へ変更しない。Java配列を変更せず、生ログをGitへ保存しない。

## 次の実機確認

1. 検証用ワールドで、水平のカーブを作り、カント整形等で中央カントが0以外になる状態にする。コピー時は同じモデルを持つか、空手で元モデルを使用する。
2. 複線コピーを4m程度に設定し、コピー予定の始点と進行方向をプレビューで確認する。周囲に接続先がない場所へコピーし、比較用の結果を残す。
3. 別のコピー予定位置に、**カントなしの短い直線**を用意する。その未接続端点が、コピー予定の始点と位置・接線方向で一致するように置く。プレビュー始点が吸着する範囲は0.5m以内。直線の反対端・周囲には不要な接続先を置かない。
4. 同じカント付きカーブを、この直線の端部へ**始点吸着**してコピーする。元カーブとコピー後の中央付近を比較する。旧版では、カントが中央で抜ける・接続先に近いカントへ変わる症状が起き得る。接続先や元のカント値によるため、見た目だけでは必ず再現するとは限らない。
5. 最新版で同じ操作を行い、端部・中央カントがコピー元に維持されることを確認する。接続端も直線へ合わせて0にはしない（開発者の追加指定）。診断の`edge/center/random`で、`copy-source`と`created`を比較する。向きが逆なら単なる符号ではなく、世界座標で左右どちらが高いかも比較する。
6. 確認後はUndoも行う。画像・操作順・モデル名と`logs/latest.log`を共有する。既存の不正なコピーは自動修復しないため、修正版で新しくコピーして確認する。

旧版と比較する場合は作業中ワールドを使わず、検証用ワールドの複製を用いる。通常の水平コピーで非再現でも、**始点が中央カントの違う既設レールへ吸着する条件**は別に確認する。

標準モデルでも再現し、元とコピーのカントおよび境界が連続ならnative描画候補を優先する。コピー後だけカントや境界に不一致がある場合はSRBX側を追加調査する。

## 自動検証と限界

中央カントの引継ぎ漏れは両版の実際の端点解決関数へ回帰条件を追加し、修正前に失敗、修正後に成功した。中央0/正/負、端点両index、接続先の端カントの符号、ランダムカントの保持、既設RP不変、非有限値拒否、明示値なしの従来継承を確認した。合成レールの高さ/pitch・境界診断の既存テストも維持する。Minecraftでの再現・修正確認とモデル固有スクリプトの照合は未実施。
