# KaizPatch / AE のブロック境界端点

> 2026-10-10更新: mainは完全自由点仕様へ戻し、両版SRBXPatchを併用する方針へ変更済み。本資料は境界方式の試作記録。 現在の導入・確認手順は[SRBXPatch](srbx-free-endpoint-mod.md)を参照。

## 判断と実装

ブロック内部の接続点では、端点を越えた予測位置が旧道床のセル内に残る。KaizPatchでは旧レールへの再選択、AEでは端部への投影・停止が起こり得る。端点を横切るブロック境界へ配置すれば、端点の前後で探索セルを切り替えられるため、SRBX側の対処として採用した。実装の幾何条件を検証済みだが、両Modの実機走行での解消は確認待ち。

2026-10-10からKaizPatch/AEのみ、共通 `SRBXRailBoundary` と各compatで次を適用する。通常RTMのmc1710/mc1122は従来の配置を維持する。

- XまたはZが整数で、端点の接線がその面を横切ることを条件とする。面に沿っているだけの点は採用しない。自由点は接線方向で近い境界へ補正し、勾配に合わせて高さも補正する。
- ownerBlockは実際の内向き接線側のセル。native directionは横切る面へ合わせ、精密なanchorYawは保持する。例えばX面だけを横切るyaw45°はdirection2となる。方向を45°刻みに丸めるだけでは、隣接探索が違うZセルへ進む場合がある。
- 共有点は同じ座標を使う。複数の接線が単一面を共有できない場合はX/Z両方が整数の角へ合わせる。
- レール生成A、複線コピー、レール移動、レール分割、カント整形、分岐生成のプレビューと適用を対応。サーバーでも実際の既設RailPositionを再検証する。
- 分割/途中分岐は元RailMap上の近傍境界交点を選ぶ。カントによる高さ補正を除いた端点を使う。分割前後3 m超の条件は維持する。
- 生成Aの円弧は同じ半径の曲線上で境界交点を選ぶ。固定半径と既設端点などの制約が両立しなければ適用を拒否する。
- 縦曲線の途中接続点も境界へ補正し、共有座標・接線勾配を揃える。区間長に応じたアンカー補正を行うため、補正後の縦曲線は指定半径の厳密な円弧とは限らない。プレビューも同じ計画を使う。補正で区間が極端に短くなる場合は拒否する。
- 移動のUndo/内部ロールバックは境界補正を行わず、保存された精密座標・direction・ownerを復元する。

既存ワールドを一括変更する処理はない。内側にある既設接続点へ新設側だけを寄せると接続が切れるため、その接続や整形は拒否する。既存線を修復する際は、接続する論理レールをすべて選んだ平行移動で両端を補正するか、接続全体を境界上へ作り直す。片端だけの修復は他方の端点も境界条件を満たす場合に限る。

境界配置は道床所有競合、交差線、脱線、既設の異常なdirection、Mod固有の探索不具合をすべて解決する保証ではない。通常道床を上書きしない規則は維持する。

## 実施した検証

- 全4ターゲットの `pnpm build` がwarningなしで成功。
- `pnpm test:rail-boundary`: 負座標、対向接線、方向別のnative隣接セル、共有点、曲線分割、円弧半径、縦曲線共有点、要求データ非破壊を確認。
- KaizPatch/AEの生成・移動・Undo・接続カントの回帰テスト。非境界操作の拒否が破壊前であること、Undoで旧精密座標を保持することを確認。
- 描画patch/include展開、runtime dispatch、入力、デバッグ車両の既存テストを確認。rtm-tsや参照ツールキットを変更していない。

## 開発者の実機確認

バックアップしたワールドに修正版ZIPを導入し、KaizPatchとAEそれぞれで次を確認する。

1. 以前往復/停止した接続を境界端点で作り直し、デバッグ車両を両方向から低速で走らせる。停止・新旧レール往復・逆方向の位置飛びを比較する。
2. 斜め線形、負座標、円弧、勾配/縦曲線、カント付き接続、チャンク境界を含めて生成A/複線/分割/分岐を確認する。
3. 接続レールをまとめて移動し、共有点・走行・ホバー・Undoを確認。旧内側端点の接続拒否と、Undoの元座標復元も確認する。
4. カント整形の端点/中央/任意点分割を確認する。短い区間や両立しない固定半径では拒否され、既設レールが変化しないことを確認する。

不具合時は操作、方向、速度、時刻と `logs/latest.log`（AE）/`logs/fml-client-latest.log`（KaizPatch）を共有する。車両の `[SRBX train debug]` とツールの診断を比較する。生ログをそのままGitへ追加しない。
