# RailPosition自由化の調査と試験実装

## 概要

KaizPatchX v1.10.2で追加された `RailPosition#setPosition(x, y, z)` は、レール曲線の端点を従来のブロック面中央に限定せず、ワールド座標で直接指定するAPIです。SuperRailBuilderXでは、この挙動を確認するための `SuperRailBuilderX_RailPositionTest` を追加しています。

公式説明: [KaizPatchX v1.10.2](https://github.com/Kai-Z-JP/KaizPatchX/releases/tag/v1.10.2)

## 内部で何が変わるか

RailPositionには従来からブロック座標、向き、高さなどがあり、それらから標準の端点座標が計算されます。自由化では標準座標との差分が `offsetX / offsetY / offsetZ` として保持され、`setPosition` がその差分を計算して端点を再初期化します。オフセットはNBTにも保存されます。

重要なのは、次の2種類の座標が別の役割を持つ点です。

| 座標 | 主な役割 |
| --- | --- |
| `blockX / blockY / blockZ` | RailPositionを所有するブロック、探索・保存上の基準 |
| `posX / posY / posZ` | 実際に曲線の端点として使われる精密なワールド座標 |

したがって、端点を動かしても所有ブロックが自動的に移るわけではありません。またRailPosition同士の同一性判定にはブロック座標が使われる箇所があり、精密座標だけを見ればよいとは限りません。

## 接続に関する制約

APIはブロック端から外れた座標も受け付けます。しかし、公式説明のとおり、列車が別レールへ正常に乗り移れる位置であることはスクリプト側で保証する必要があります。見た目の曲線が接していても、所有ブロック、RailPositionの向き、隣接判定との組み合わせ次第で接続として扱われない可能性があります。

試験ツールは理解のために任意位置へ移せるようにしています。実用ツールへ発展させる際は、接続相手の端点へのスナップ、ブロック境界への制限、接続可否の事前検証を追加する想定です。

## 試験ツールの操作

1. ツールを使用し、視線の衝突位置から半径約1ブロック以内にある通常レール端点を探します。
2. 表示された点の近くで右クリックし、最も近い端点を選びます。
3. 視線先に0.01 m単位で丸めた移動先プレビューが表示されます。
4. 右クリックで移動先を確定します。
5. Enterでサーバーへ適用を要求します。
6. 左クリックは、移動先確定から移動先選択へ、端点選択から未選択へと1段階ずつ戻します。

クライアントは探索、入力、プレビューだけを担当します。サーバーはRailPositionの元座標が選択時から変化していないか再検証し、成功時に `setPosition`、RailMap再生成、保存・同期処理を行います。

## 現在の安全制限

- KaizPatchXターゲット専用です。他ターゲットでは候補を表示せず、適用もしません。
- v1.10.2の自動チャンク分割で作られた `TileEntityLargeRailSectionCore` は対象外です。セクションコアの論理RailPositionはコピーとして返され、通常レールと同じ更新では全体の論理曲線を安全に書き換えられないためです。
- 通常レールでも大きく端点を動かすと、既存のレール構成ブロック範囲と曲線が一致しなくなる可能性があります。初期試験では小さな移動を推奨します。
- Undoはまだありません。適用前の左クリックによる段階解除のみです。

## 今後の実装候補

- 接続可能な端点へのスナップと接続成立判定
- 移動前RailPositionのサーバー側バックアップによるUndo
- RailMapの新旧占有範囲を比較した構成ブロック更新
- セクションレールを論理レール単位で解体・再構築する専用処理
- X/Y/Z軸固定、数値入力、移動量表示
