# AppleExtended向け：自由端点・重複レールの走行先判定設計

作成日: 2026-10-12。対象: Minecraft 1.12.2 / AppleExtended 2.5.3。

AE側で独自に再実装するための設計資料です。SRBXPatchのコード移植やCoreModの採用を前提にしません。現在の実装を根拠に、解決する現象、判定の考え方、参考アルゴリズム、検証条件を説明します。AE本体への実装・検証はまだ行っていません。

## 1. 解決したい現象

### 重複する道床による別レールへの吸着

複数のレールが同じブロックを通ると、道床タイルの所有コアは、台車が走っている線形のコアと一致しないことがあります。予測位置の道床だけから走行先を選び直すと、現在レールの途中でも別のレールへ切り替わります。

例: A線とB線の道床が重なる場所をA線上で走行中、予測位置の道床がB線を参照しているためB線へ移る。A線の形状自体は有効で、端点も越えていません。

### 自由端点とブロック所有先の不一致

RailPositionの精密端点を変更しても、コアや道床のブロック座標が同時に移るとは限りません。端点がブロック内部にあると、端点を越えた予測位置でも元レールの道床を引く、または接続先の道床を引けないことがあります。見た目が接するだけでは、安全な走行先の選択には不十分です。

### 自動分割境界での別線への移行

自動分割レールでは、同じ論理レールを複数のセクションコアが構成します。内部境界の道床が別線の所有になっていると、本来隣接するセクションへ進めません。ここでは論理グループのコア情報を使い、接続する同一グループのセクションを優先します。

AE 2.5.3の調査では、走行予測後の `resetRailObj` が `getRail(x,y,z)` を呼び、`getRailFromCoordinates(world,x,y+2,z,0)` で見つけた道床のコアを使います。コア変更時はmap・分割数を更新し、前回indexを初期化します。この道床探索の前に、以下の走行先判定を追加するのが再実装の候補です。

## 2. 設計の中心となる考え方

1. **現在走行している線形を継続の根拠にする。** 生存する現在mapの上に台車と予測位置がある間は、重なった道床の所有コアを理由に乗り換えない。
2. **端点を越えたときに接続先を判定する。** 継続保持より先に端点越えを調べる。線形への距離だけでは、端点直後でも元mapの末端に近いため保持してしまう。
3. **候補の発見と、接続の成立を分ける。** 道床やグループ一覧はコアを発見する手段。実際に採用するには、精密端点・向き・予測位置・高さを検証する。
4. **分岐は既存の選択中経路に従う。** 全mapから都合のよい経路を選ばず、AEの既存切替処理が使う経路を検証する。
5. **確定できないときは既存処理へ戻す。** 未ロード、削除済み、状態不整合、候補競合では独自判定を成立させない。既存処理への復帰は「走行が必ず成立する」という保証ではない。

この判定は走行先コアの選択だけを担当します。ワールド・道床所有先・保存データ・端点座標を変更しません。採用後のmap更新や移動予測の継続はAEの既存処理へ渡します。

## 3. 入力と判定結果

| 記号 | 内容 |
| --- | --- |
| B | 台車の現在位置。XZは前回線形サンプルとの整合確認にも使う |
| P | 既存の走行予測が計算した次の位置。任意の目標座標ではない |
| C / M | 現在のコア / 現在のRailMap |
| N / i | 現在mapの分割数 / 前回位置index |
| S / E | 現在mapの精密始点 / 精密終点 |
| d | XZ平面での移動量 `hypot(P.x-B.x, P.z-B.z)` |

結果は「現在コアを保持」「接続先コアを採用」「独自判定では決まらない」の3種類にします。現在パッチはコアまたはnullを返していますが、AEでの型やAPIは自由に設計できます。後者をレール不存在と同一扱いにせず、既存探索へ続けてください。

## 4. 判定の順序

以下は概念上の擬似コードです。関数名はAEの実APIを指定するものではありません。

```text
resolve(B, P, C, M, N, i):
    サーバー側でない / 入力や前回状態が不正 → 未決定
    現在コアが生存しない / 現在mapが現在コアに属さない → 未決定
    台車の現在XZが前回サンプルから離れている → 未決定
    予測Yが前回サンプルの高さと大きく違う → 未決定

    近傍の始点または終点の接線平面を予測位置が越えた場合:
        出口方向に移動していない / 出口から不自然に遠い → 未決定
        自動分割レール:
            同一論理グループの接続先を検証
            複数の異なるコアが成立 → 未決定
            1コアだけ成立 → 接続先採用
        出口がブロック内部の自由端点:
            ロード済み近傍道床から候補コアを集めて検証
            1コアだけ成立 → 接続先採用
        未決定（通常のブロック境界での接続は既存探索へ）

    前回index近傍で予測位置が現在map上にある:
        現在コアを保持
    未決定
```

同一グループの探索で複数コアが成立した場合は、その時点で未決定にします。近傍道床の探索によって恣意的に競合を解決しません。同一グループに成立候補がない場合のみ、自由端点なら近傍探索へ進みます。

## 5. 現在レールを保持する条件

### コアとmapの生存確認

コアが無効化されていないこと、所有ブロックがロード済みであること、そのブロックの現在TileEntityが同じコアであることを確認します。現在mapもコアが返すmap一覧に同一インスタンスとして残っている必要があります。撤去・再生成後の古い参照から、失われたレールを保持しないためです。

`N > 0`、`0 <= i <= N`、有限の座標と移動量を要求します。現在台車XZと `M.getRailPos(N,i)` のXZが近いことを確認し、テレポートや古いindexを根拠に接続させないようにします。

### 局所的な線形への近さ

前回indexの前後を、今回の移動量に応じた範囲だけ調べます。SRBXでは1m当たり約360分割を使い、範囲を `i ± ceil((d+0.25)*360)` に限定して `[0,N]` へ丸めます。全線形や全ワールドを探索しません。

最短XZ距離が許容内で、対応サンプルのレール高さ＋台車Yオフセットと予測Yが近ければ保持します。高さはXZが重なる高架・地上線を区別するために必要です。現在パッチの保持条件は、選択中mapがコア内に残っていることを確認するもので、走行中の分岐切替への追従仕様全体を定義するものではありません。

最適化として、前回地点の接線へ移動差分を投影し、予測indexを先に試せます。

```text
t(yaw) = (sin(yaw), cos(yaw))       // yawはラジアンへ変換
j = clamp(i + round(dot(Pxz-Bxz, t(localYaw))*360), low, high)
```

予測サンプルとの距離が1サンプル幅以内で高さも一致すれば、密な走査を省略します。不一致なら局所範囲の全サンプルを確認します。曲線上で接線予測が外れることを正常なケースとして扱います。

**座標順に注意:** 現在の `getRailPos` の配列は `[Z,X]` として利用しています。AE本体ではAPIの座標規約を確認して実装してください。

## 6. 端点を越えたかの判定

RailMapのyawは始点・終点とも始点→終点方向の接線として扱います。予測位置から端点を引いたベクトルと接線の内積を使います。

```text
始点越え: dot(Pxz-Sxz, t(startYaw)) < -epsilon
終点越え: dot(Pxz-Exz, t(endYaw))   >  epsilon
始点からの出口向き: startYaw + 180°
終点からの出口向き: endYaw
```

曲線の反対側の端点平面を誤って使わないよう、前回indexがその端点に近い場合だけ判定します。参考範囲は `ceil((d+1.0)*360)` サンプル。端点yawは端そのものから1サンプル内側を参照します。

さらに `dot(Pxz-Bxz, t(exitYaw)) > 0` と `distanceXZ(P,出口) <= d+0.25` を要求します。端点付近でも出口へ進んでいない状態、または遠方の端点を横切ったように見える状態を除外します。

### 自由端点と通常境界

現在パッチは、進行接線に成分がある軸で精密端点が整数座標のブロック境界に一致するかを調べます。X方向成分がありXが整数、またはZ方向成分がありZが整数なら通常境界扱い。それ以外を内部自由端点として近傍探索の対象にします。接線がその境界に沿うだけの場合は、境界を通過する条件に含めません。

同一グループのセクション接続は、通常境界でも優先判定します。通常境界でそれが成立しない場合はAEの既存探索へ戻します。この分類は現行パッチの探索範囲を限定する方針であり、AEが接続トポロジーを直接保持する場合に必須の区分ではありません。

## 7. 接続候補の発見と検証

### 候補の発見

自動分割レールはグループのコア座標一覧から候補を取得します。ロード済み・生存するSectionCoreで、現在コアと同一論理グループに属するものだけを調べます。座標一覧が古い場合もあるため、一覧掲載だけで採用しません。現在パッチは一覧が4096件を超える場合、この探索を行いません。

内部自由端点は、出口の精密座標をfloorしたブロックを中心にX/Z各±1、Y±2の45ブロックを調べます。ロード済み道床からコアを取得し、同じコアは一度だけ検証します。未ロードチャンクをロードせず、現在コア・削除済みコア・現在mapと同一の候補を除外します。

AEに接続先の索引や明示的な接続情報がある場合は、それを候補発見に利用できます。その場合も以下の検証を維持してください。45ブロック探索は既存APIを使う暫定実装であり、設計上の必須条件ではありません。

### 候補の選択中map

通常コアは台車を引数にした `getRailMap`、分岐コアは `getSwitch().getNearestPoint(bogie).getActiveRailMap(world)` を使っています。AEが実際のコア切替で選ぶmapと同じ規則に揃えます。非選択の分岐mapだけが接続している場合は採用しません。

### 物理的な接続の条件

候補mapの始点・終点のそれぞれについて次を確認します。

1. **端点一致:** 出口端点とのXZ距離とY差が許容内。
2. **向き一致:** 候補へ入る向きと元mapから出る向きが一致。候補始点への入口はyaw、候補終点への入口はyaw＋180°。
3. **予測の進入:** 出口からPへの内積が候補の内向き方向で非負、かつ候補長を大きく越えていない。
4. **線形一致:** 候補入口から今回移動し得る範囲のサンプルを調べ、PのXZ距離と高さが許容内。
5. **一意性:** 成立する異なるコアが1つだけ。同じ位置に複数コアが成立しても、列挙順や最初の候補で選ばない。

候補長は有限・正数で、サンプル数への換算が整数範囲に収まることも確認します。検証成立後はコアを返し、実際のmap交換、index初期化、残りの移動予測は既存処理に任せます。

## 8. 現行パッチの参考値と意図

以下は実装上の参考値です。AE側の速度・線形精度・高さ規約に合わせて検証し、採用値を決めてください。

| 判定 | 参考値 | 意図 |
| --- | --- | --- |
| 1回の予測XZ移動量 | 最大10m | 異常な状態差を独自判定から外す |
| 現在XZと前回サンプル | 最大0.25m | 古いindexやテレポートを外す |
| Pと線形のXZ距離 | 最大0.125m | 別線や線形外の予測を外す |
| P.yとレール高さ＋台車offset | 最大0.75m | 高さが違う候補を外す |
| 接続端点のXZ差 | 最大0.001m | 近いだけの非接続レールを外す |
| 接続端点のY差 | 最大0.03m | 精密端点の高さ一致を確認 |
| 入口向きと出口向き | 内積cos値が0.95以上（約18.2°以内） | 逆向き・大きな折れを外す |
| 端点平面のepsilon | 1e-7m | 境界上の数値誤差を吸収 |
| 境界判定の接線成分 | 絶対値が1e-6より大きい | 境界に沿う接線を除外 |
| サンプル密度 | 約360/m | 前回index近傍での探索 |

端点Y差0.03mと予測高さ差0.75mは別の条件です。前者は線路同士の接続、後者は台車予測と線形の整合を検証します。0.75m以内の上下別線を高さだけで完全に区別できるとは限らないため、端点・方向・一意性の条件も必要です。

## 9. AE側での再実装範囲

推奨する最小範囲は、既存の道床探索の前に端点越え・接続先判定を置き、端点を越えていない場合に継続保持を判定し、未決定なら元の処理へ進む構成です。再実装ではAEの型・APIを直接使えます。SRBXPatchの反射、ASM、LoadingPlugin、SRBXの生成ツールへの依存は不要です。

初回のレール取得、クライアント描画、速度計算、分岐切替操作、敷設・道床所有先変更、保存形式は本資料の対象外です。今回の走行先判定を導入しただけで、SRBXの全機能がAE本体に統合されるわけではありません。

本体実装と旧SRBXPatchの両方が判定すると、旧フックが先に結果を返す可能性があります。本体対応版の評価はSRBXPatch JARを外して行い、配布時は本体対応版で旧パッチを不要とする導入案内や、旧パッチ側の適用抑止方法を検討してください。

## 10. 再実装後の確認項目

| ケース | 期待する判定 |
| --- | --- |
| 重複道床が別コアを参照する区間を正逆方向へ走行 | 端点を越えるまで現在mapを保持 |
| 自由端点手前・越え直後・次Tick・逆方向での通過 | 手前は保持、越えたら接続先、その後に旧mapへ吸着しない |
| 通常ブロック境界での接続 | 同一グループ優先以外は既存探索へ |
| 自動分割境界の道床が別線所有 | 同一グループの物理的に接続するコアへ移行 |
| グループ一覧内に別グループ・削除済み・端点不一致のコア | 不適切な候補を採用しない |
| 近くにあるが端点不一致、向き不一致、高さ違いの線路 | 接続先として採用しない |
| 接続する分岐mapが非選択 / 選択中 | 非選択は拒否、選択中だけ検証して採用 |
| 複数の異なるコアが条件を満たす | 未決定として既存探索へ |
| 撤去・再生成、未ロード、初回取得、古いindex、テレポート | 古い参照を保持せず既存探索へ |
| 曲線・勾配・カント・高速走行・短区間 | 接線最適化失敗時も局所走査で確認、境界越えの誤保持を確認 |
| SRBX未導入ワールド、SRBXPatch JARなし | AE単体の通常走行を維持 |

既存の模擬テストは重複区間、自由端点正逆移行、同一グループ境界、候補競合、選択分岐、削除・未ロード・高さ・古い状態、曲線の接線最適化を含みます。全速度・全曲線・全カント・全分岐条件の実機確認が済んでいるという意味ではありません。

2026-10-11に開発者からAE重複区間・自動分割境界対策の実機確認済みとの報告を受領しています。AE 2.5.3実JARに対する既存ASM検証もありますが、AE本体で再実装した版の動作を保証するものではありません。

## 11. 残る制約と改善候補

- 近傍に接続先を指す道床がなければ、現在の近傍探索は候補を発見できません。コアが近傍の外でも、近傍道床から参照できれば発見可能です。
- 複数の極短レールを1Tickで越える連続接続は、この1回のコア選択では保証しません。再実装で対応する場合は残り距離と反復上限を持つ別の検討が必要です。
- 同一セルのコア競合や敷設不能は、走行先の選択では解決できません。
- 接続トポロジー索引は改善候補ですが、撤去・生成・分岐変更・チャンクのロード状態との整合を別途設計する必要があります。
- 性能評価は直線中間だけでなく、曲線の走査フォールバック、候補競合、分割グループ探索、多数台車を含めます。world/core/map/台車の参照を長期キャッシュして生存判定を省略しないでください。
