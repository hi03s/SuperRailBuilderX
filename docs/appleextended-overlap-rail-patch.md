# AE重複レールの吸着とSRBXPatch試作

## 結論と実装

AE v2.5.3では、現在レールの途中でも予測位置の道床が参照する別コアへ切り替わり得る。既存SRBXPatchの保持条件は自由端点付近だけだったため、重複区間の途中は標準探索へ戻っていた。実機報告と整合する経路を特定し、AE版パッチで現在の生存するRailMap上を走る間の保持を区間全体へ拡張した。今回の現象の走行ログは未取得で、実機で解消したとはまだ扱わない。

AE EntityBogieの実バイトコードでは、走行予測後のresetRailObjがgetRailを呼ぶ。getRailはgetRailFromCoordinates(world, x, y + 2, z, 0)で道床を探し、そのgetRailCoreを返す。コアが変わればcurrentRailObj/currentRailMapを入れ替え、splitを再設定しprevPosIndexを-1へ戻す。現在の線形と新コアの接続性を確認してから選ぶ処理は、このresetRailObjにはない。

比較したKaizPatchXのv1.10.4ソース（d70ef47）では、findCrossedConnectedCoreを先に試し、道床がなければfindConnectedCoreも試し、keepCurrentSectionCoreによる同一論理セクションの保持も行う。resetRailObjにはcanConnectによる接続検査もある。ただしKaizも道床探索を使うので、すべての重複配置を正しく識別できるという意味ではない。

AEの試作変更はAEFreeEndpointHookのみ。既存ASMのgetRail先頭フックを使い、道床・コア・保存データの所有先やパック生成処理は変更しない。Kaiz版JARも変更しない。

- 生存/ロード済みコアに現在のmapが残り、台車が前回サンプルから水平0.25m以内で、予測点が現在線形から水平0.125m以内かつ高さ条件を満たすとき、現在コアを保持する。
- 途中の予測には端点の向きではなく現在サンプルの接線を使う。合致時は近傍の全点走査を省略する。
- 近い端点の外へ出たときは保持しない。内部自由端点なら従来の精密接続探索、自動分割内部境界では同一グループの隣接コアを優先し、それ以外のブロック境界端点なら標準処理へ渡す。
- クライアント、未初期化map、削除/置換/未ロードmap、前回位置の不整合、異常座標/高さ/大きな移動は標準処理へ戻す。反射失敗時は警告してhookを無効化する。

初回配置・再読込直後など現在mapがまだないときは標準探索のまま。完全に重なる2線のどちらへ新規配置するかを、この修正だけで指定することはできない。すでに別レールへ吸着した台車も自動で元線へ戻さない。複数候補がある接続先、複数の極短区間を1 Tickで越える問題は別の制約として残る。

## 検証

Java 8の-Xverify:allで、途中の重複道床を用意した双方向保持、曲線の接線/短い探索、境界端点内側保持と両端の標準遷移、線形外予測、map置換/初回取得の標準復帰を追加検証した。従来の自由点双方向遷移、削除/未ロード/高さ/位置不整合/曖昧候補/分岐の選択中経路も成功。

正式AppleExtended-forge1.12.2-v2.5.3.jarの実EntityBogieへASMを適用し、BasicVerifierと二重適用防止を確認した。対象JARのSHA256は25296F16E99C65A58A6F2A4699224A241460306C7AF8D1E3F4244E0B94B43840。生成JARはJava 8 class形式、パック/依存/テスト非同梱をbuild.pyで検証した。診断ON/OFFともテスト成功。

実Minecraftの通常/自動分割/分岐・重複走行・サーバー/クライアント同期とCPU負荷は未検証。今回はJavaパッチ変更だけなのでTypeScriptのbuild/ZIP更新はしていない。本番サーバーは操作していない。

## 実機確認

1. 検証環境を停止してSRBXPatch-v1.0-1.12.2.jarを置き換える。シングルプレイならそのMinecraft、専用サーバーなら検証サーバーのmodsへ入れる。パックZIPとKaiz JARの変更は不要。
2. 起動ログの「AppleExtended EntityBogie hook installed」を確認する。
3. 重複していない区間から、移動したレールを双方向・低速/通常速で通過する。通常/自動分割、曲線、境界端点/内部自由端点を試す。既設側からも通過し、両方とも途中で別線へ切り替わらないことを確認する。
4. 分岐の切り替え、移動/Undo後、保存/再入場後を確認する。初回取得は別問題なので、重複セルへの新規車両配置とは分けて試す。
5. 問題が残る場合はJVM引数に-Dsrbxpatch.debugRailLookup=trueを追加して再検証する。[SRBXPatch AE lookup] retainedが最大1秒に1行、保持コア座標/前回index/split/予測座標を出す。診断は保持を記録するもので、吸着の原因を単独で確定するログではない。
6. 操作順・方向・発生時刻・重複配置を添えてlogs/latest.log（専用サーバーなら検証サーバーログも）を共有する。

## 2026-10-11 自動分割境界の追加対策

現行SRBX敷設では、通常道床配置が既設BlockLargeRailBase/TileEntityLargeRailBaseを保持し、論理端部の所有先変更はTileEntityLargeRailCoreを除外する。Sectionは通常コアの派生型なので除外対象。新コアの配置も全ownerを変更前に再検証して既設コアなら拒否する。コア競合では代替配置/逆順/設定上限内の通常生成を試すが、既設コアを上書きするルールではない。AEのprepareBaseBlocksもバイトコード上、配置先BlockLargeRailBaseを除外する。既設通常道床を新Sectionコアへ昇格する場合はあるが、既設Sectionコアの置換とは区別する。

前回パッチは物理区間の境界端点を越えると標準道床探索へ戻していたため、コアが残っていても既設側の道床所有先へ遷移し得る。これを同一論理レールのgetRailGroupCorePositionsとisSameLogicalRailを使った優先探索へ変更した。ロード済み・生存・同一グループで、物理端点/進行方向/予測線形/高さが一致する次コアのみを返す。道床の所有先を辿らず実コア座標を見るので、移動に伴ってコア位置が境界から離れた場合も対象にできる。正確な1候補がない場合は従来経路へ戻す。未ロードのチャンクを強制ロードしない。

検証: 境界の道床を別線へ向けた状態で同一グループを双方向に選択し、別グループ/削除コア/ずれた接続点を拒否。既設Sectionコアが生成直前に競合した場合の無変更/生成拒否をスクリプトテストへ追加。AE Java回帰・実AE ASM検証・pnpm test:appleextended成功。敷設スクリプト本体の変更なし、パックZIP/Kaiz JARの更新不要。

2026-10-11に開発者から、AE重複区間・自動分割境界対策は実機で確認済みとの報告を受領。個別の全ケースを確認済みとは扱わず、今後の再発時は-Dsrbxpatch.debugRailLookup=trueを付けたAEログと操作順を共有する。診断は最大1秒1行でretainedまたはsection transition（元/先コア座標）を出力する。診断の間引きにより全境界イベントが出るとは限らない。本番サーバーは操作していない。
