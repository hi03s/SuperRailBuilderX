# ツール切り替えホイール

全6ツールの操作中にTABを長押しすると、暗い背景の上に中央が空いたリングを表示する。内外の円と放射状の仕切りで6区画に分け、各区画へアイコンと名前を配置する。真上から時計回りに、レール生成A、線路分割、線路移動、複線コピー、カント整形、分岐生成を配置する。選択中の区画は背景色と黄色の名前で強調する。

- マウスを中心から選びたいツールの方向へ動かす。中央の「変更なし」エリアへ戻すと、現在使用中のツールが選ばれ、切り替えを取り消せる。描画と判定で同じ内径を使う。
- ←/→でも反時計回り/時計回りに選べる。マウスを動かさなければキーで選んだ項目を維持する。
- TABを離すと選択したモデルへ切り替える。同じツールを選んだ場合は変更しない。
- 左クリックでも決定して閉じる。クリック座標から選択を更新するため、中央でクリックすると切り替えない。右クリックでは決定しない。
- ESCは切り替えをキャンセルする。クリック決定/ESCの後、TABを押し続けても再度開かず、一度離してから開く。

専用GuiScreenを開いてマウスを解放し、通常ツールの入力とプレビューを止める。ゲームを一時停止しない。切り替え後もボタン・矢印キーを離すまで入力を止め、押しっぱなしによる誤選択を防ぐ。この待機状態は新しいモデルのスクリプトにも共有する。

標準GUIを開く際のキー解除でTABのプレイヤーリスト入力を抑える構成。描画は標準の画面レイヤーなので、リストが残る環境でもリストより上に表示する。KaizPatch/AEの実マルチプレイでの非表示は未確認。キー設定を書き換えない。

モデル変更はサーバーで実行する。操作プレイヤーがツールの所有者であること、対象がSRBXの6モデルのいずれかで存在すること、生成/移動/Undoなどの処理要求が残っていないことを再検証する。処理要求が送信中ならメニューを開かず、サーバーでも競合する切り替えを拒否する。エンティティを置き換えず、切り替えたツールの処理を次Tickから使用する。ワールドのレールを書き換える操作は行わない。

描画にはSRBXToolGuiの行列/属性の個別保存・復元を利用し、GLのPush/Popは使わない。エラー時はメニューを閉じて無効化し、`[SuperRailBuilderX wheel]`または`[SuperRailBuilderX GUI]`へ診断を記録する。サーバーは切り替え結果を`[SuperRailBuilderX wheel] target=..., result=...`へ記録する。

## 検証

- `pnpm build`、`pnpm test:input`、`pnpm test:gui`で6方向、マウス/キー/解除/キャンセル、入力抑止、所有者/処理中/モデル検証と、アイコン/名前/GL復元を確認する。
- ゲーム同梱Java 8u51で`builder1_gui_nashorn.test.js`を実行し、ホイール描画のGL復元を確認する（GLは模擬）。`javac -source 8 -target 8 -d artifacts/test-classes tests/srbx_patch/ToolWheelScreenFixture.java`の前に出力ディレクトリを作成し、`jjs -cp artifacts/test-classes -scripting tests/srbx_patch/tool_wheel_nashorn.test.js`で実際のJava.extendとSRG名の画面コールバックを検証する。画面本体は検証用のJavaクラスで、実Minecraft GUIの検証とは区別する。
- 実機では更新ZIPに置き換え再起動し、KaizPatch/AEで全6ツールからTABを開く。6区画リング/中央の穴、暗い背景、マウス・←→、TAB解除/左クリック決定、中央へ戻して解除/クリックした場合の変更なし、ESC、クリック決定後のTAB押しっぱなし、切り替え直後の誤クリック抑止、Q終了を確認する。生成/適用/Undo中の切り替え拒否、マルチプレイのリスト表示と他プレイヤーへの影響も確認する。
- 不具合時はツール名、選択方法、操作順と`logs/latest.log`を共有する。本番サーバーでの操作は行わない。
